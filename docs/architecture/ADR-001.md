# ADR-001: Stack Selection — CareBridge Canada (from-scratch build)

- **Status:** Approved by Eric (founder), 2026-09-24 — scaffolding authorized
- **Date:** 2026-09-24
- **Deciders:** Eric (founder) + build agent
- **Governing brief:** CareBridge-Canada-Astra-Master-Prompt v2.1 (§23.1, step 1)

## Context

Greenfield build of CareBridge Canada, a healthcare access / navigation / orchestration
platform. Controlled Regina, Saskatchewan pilot first. Hard constraints from the brief:

- Canadian data residency preferred; every service's processing region must be recorded (§4).
- Tenant isolation, deny-by-default server-side RBAC + ABAC, 16 canonical roles (§5, §6).
- Append-only audit, transactional state machines, idempotency (§5, §7).
- React/TypeScript component system for the Liquid Glass design language (§14).
- WCAG 2.2 AA, performance budgets (§15).
- Synthetic data only; `PHI_PRODUCTION_ENABLED=false`, `PAYMENTS_ENABLED=false`,
  enforced server-side in every environment (§20, §23).
- Modular monolith is explicitly acceptable; premature microservices are not required (§5).

## Decision

| Layer | Choice |
|---|---|
| Language | TypeScript (single language, end-to-end typed contracts) |
| Application framework | Next.js 15 (App Router) — modular monolith: public site (`/`), patient app (`/app`), API routes, background jobs in one deployable unit |
| Database | PostgreSQL 16 with Row-Level Security (RLS) — tenant isolation enforced at the DB layer, not just in app code |
| Data access | Drizzle ORM (SQL-first, versioned migrations) + hand-written SQL for RLS policies, triggers, and append-only audit rules |
| Authentication | Custom server-side sessions (secure httpOnly cookies) + SimpleWebAuthn (passkey/WebAuthn) + TOTP via `otplib` + recovery codes. No third-party IdP. |
| Hosting region | AWS `ca-central-1` (Montreal): compute (ECS Fargate), RDS PostgreSQL, S3 private buckets (evidence files, quarantined uploads), SES for email |
| Test runners | Vitest (unit/integration) + Playwright (e2e, accessibility spot checks) |
| Static checks | ESLint + `tsc --noEmit` |
| CI | GitHub Actions on every PR and push to `main` (install, lint, typecheck, test, security scan) |
| Secrets | Managed secret storage (AWS Secrets Manager); `.env.example` with blank values; never in chat |

## Alternatives considered

- **NestJS API + separate SPA:** more deployables and contracts to maintain; slows the
  vertical-slice cadence the brief demands. Rejected for now; the monolith can be
  split later via an ADR if a bounded context justifies it.
- **Supabase / managed Postgres outside Canada:** no Canadian region option keeps
  identity and (later) PHI data where the brief wants it. Rejected.
- **Prisma:** heavier abstraction; its migration engine fights hand-written RLS
  policies and triggers. Drizzle's SQL-first approach fits the policy-heavy schema.
- **Auth0 / Clerk / other IdPs:** US data processing and less control over assurance
  levels, step-up auth, and session semantics the brief requires (§6). Self-built
  sessions keep everything in `ca-central-1`.

## Consequences

- The team owns auth security directly: WebAuthn/TOTP/session code gets dedicated
  negative tests in Sprint 1 (MFA-less privileged denial, session fixation, etc.).
- RLS policies are load-bearing: every slice needs Clinic-A-cannot-read-Clinic-B
  tenant-isolation tests (§25 definition of done).
- AWS `ca-central-1` has a smaller service footprint than `us-east-1`; verify each
  managed service's availability in-region during Sprint 0 and record it in the
  processor inventory (§4).
